## 二、大模型本质：一个超大的函数

### 2.1 最简模型

大模型本质上就是一个**函数**：

```
f(x) = Wx + b
```

- **模型结构** = 函数长什么样
- **模型参数** = 函数里的 W 和 b

普通线性函数只有 2 个参数，而大模型有**上亿个参数**（GPT-3 有 1750 亿个）。

> 核心洞察：参数无非是一堆数字。填对了就是好模型，填错了就是烂模型。**训练大模型本质上就是「填数字的游戏」**。

### 2.2 训练数据的来源问题

- 以当前模型规模，把互联网数据全挖干净也喂不饱
- 案例：SROP 曾下载 700 万本盗版书籍，被创作者联合起诉，最终赔偿 15 亿美元
- 即便数据被删除，模型（参数）已经训练出来了，无法回滚
- 由于 AI 厂商频繁爬取数据，网站设置越来越多的防御机制

## 三、开源（Open Source）的语义演变

### 3.1 传统意义
开放源代码（任何人都可以查看、修改、分发）

### 3.2 大模型语境下的意义
**仅指开放权重**（即模型参数），而不是传统意义上的开放全部源代码

> **关键区分**：在大模型语境下，「开源 = 公开这些数字（权重）」，「闭源 = 把这些数字藏起来，只对外提供服务」

## 四、蒸馏（Distillation）的语义演变

### 4.1 原始定义（2015 年论文）
知识蒸馏：通过一个较大的**教师模型**来训练出一个较小的**学生模型**
- 学习目标是 softmax 之后的 logits（软标签）

### 4.2 现在的广义定义
只要一个模型的训练数据中使用了另一个模型的输出数据，就可以叫蒸馏

但这里有一个**模糊地带**：
- 如果训练数据中 99.9% 是互联网公开数据，只有 0.1% 来自另一个模型的输出
- 这算不算蒸馏？这已经严重偏离了原本的含义

### 4.3 常见应用场景

| 场景 | 说明 |
|---|---|
| 自家蒸馏 | 用自家大模型蒸馏出不同规格小模型（如阿里千问系列） |
| 跨模型蒸馏 | 用 GPT-4 的输出蒸馏出其他架构的模型（如 Llama） |
| 互相使用 | 互联网数据快被榨干，厂商之间互相使用对方模型输出作为训练数据 |

## 五、"蒸馏攻击"事件分析（SROP 案例）

### 5.1 事件背景
SROP 发文声称三个中国 AI 厂商对他进行了"工业级蒸馏攻击"，阅读量超 3000 万，评论区一片嘲讽。

### 5.2 SROP 的"证据"——数量级困境

| 指控对象 | 声称交互次数 | 问题分析 |
|---|---|---|
| DeepSeek | 15 万次 | 跑一个 SWE-bench 基准测试约 23 万次交互，一个人高频使用 Claude Code/Cursor 一周也能跑出这个量 |
| MiniMax | 1300 万次 | MiniMax 有自己的 API 产品，可能是成千上万人通过 API 与 Claude 正常交互积累的量 |

### 5.3 逐层反驳逻辑

```
即使交互次数和 IP 识别是真实的
    ↓ 不足以证明这是官方行为（数量太少，随便测测就到了）
        ↓ 即使是官方行为，不足以证明用于训练模型
            ↓ 即使是用于训练模型，也不足以称为"蒸馏攻击"（本来没这个词）
                ↓ 就算真的是蒸馏，也无话可说 —— SROP 自己也在用互联网数据
```

### 5.4 核心评论
- SROP 的行为像一个小孩打不过别人，找老师告黑状
- 评论区基本一边倒嘲讽
- 有些反制（如用 API 访问 Claude 问"你是谁"，回答"我是 DeepSeek"）虽然有趣但属于无效反驳

## 六、关键认知——同一词汇在不同语言下的理解

AI 领域的基础名词，在不同语境下可能有完全不同的意思。

**面对任何人的评论甚至官方文章时：**
1. 要有自己的辨别能力
2. 看它是在什么语境下说的
3. 不要被带跑偏了

## 七、个人学习收获

1. **概念溯源能力**：看到"开源""蒸馏"这些词时，要先搞清楚说话的人是在什么语境下用这个词，否则讨论都是无效的
2. **数量级直觉**：15 万次交互对于 AI 调用来说真的很少，培养数量级判断力能帮助你一眼识破似是而非的指控
3. **利益动机分析**：SROP 的指控本质上是一种带偏舆论的行为，要学会看言论背后的商业/政治动机
4. **不要把复杂问题简单标签化**："蒸馏攻击"这个新造的标签掩盖了背后复杂的数量级、技术细节和利益关系
