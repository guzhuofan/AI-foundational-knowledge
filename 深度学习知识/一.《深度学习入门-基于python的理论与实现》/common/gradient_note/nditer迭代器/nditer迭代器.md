## 我们遇到的问题
在numerical_gradient 函数中, 我们遇到了一个之前没见过的类, 这个类还是整个函数的核心所以有必要认真了解一下.
```python
def numerical_gradient(f, x):
    h = 1e-4 # 0.0001
    grad = np.zeros_like(x) # 生成一个和 x 形状一模一样的全 0 数组，用来存梯度
    
    # 【关键】创建一个迭代器，它可以遍历多维数组中的每一个元素
    # flags=['multi_index']: 告诉迭代器我们需要多维索引（如 (0,0), (0,1)）
    # op_flags=['readwrite']: 允许我们在遍历时修改 x 的值
    it = np.nditer(x, flags=['multi_index'], op_flags=['readwrite'])
    
    while not it.finished:
        idx = it.multi_index # 获取当前元素的坐标，例如 (0, 0)
        tmp_val = x[idx]     # 取出当前坐标的元素值（这是一个标量！）
        
        # ----------------------------------------
        # 下面就是标准的中心差分法求导 f'(x) ≈ (f(x+h) - f(x-h)) / 2h
        # ----------------------------------------
        
        # 1. 计算 f(x+h)
        x[idx] = float(tmp_val) + h # 修改 x 中这一个位置的值
        fxh1 = f(x) # 计算稍微变大一点后的 Loss（注意：x 此时已经被修改了！）
        
        # 2. 计算 f(x-h)
        x[idx] = tmp_val - h # 修改 x 中这一个位置的值（往反方向变）
        fxh2 = f(x) # 计算稍微变小一点后的 Loss
        
        # 3. 计算偏导数
        grad[idx] = (fxh1 - fxh2) / (2*h) # 存在对应的梯度数组中
        
        # 4. 还原现场
        x[idx] = tmp_val # 把 x 改回原来的值，以免影响下一个元素的计算
        
        it.iternext() # 移动到下一个元素
        
    return grad
```

## nditer 核心参数解析

这个函数主要用于返回索引，但它的能力远不止于此。它是 NumPy 中的 **“万能遍历引擎”**。

`it = np.nditer(x, flags=['multi_index'], op_flags=['readwrite'])`

### 1. `flags=['multi_index']`：开启“GPS定位”
*   **默认情况**：迭代器像个无头苍蝇，只知道“下一个值是 5.0”，但不知道这个 5.0 在矩阵的第几行第几列。
*   **开启后**：它会启用 `it.multi_index` 属性。
*   **作用**：每次迭代时，访问`it.multi_index`属性，它都会告诉你当前**迭代到的元素的精确坐标**（元组形式，如 `(0, 0)`）。
*   **应用**：我们需要把算出来的偏导存到 `grad` 数组的对应位置，所以必须要有坐标。

### 2. `op_flags=['readwrite']`：开启“编辑模式”
*   **默认情况**：为了安全和性能，`nditer` 默认把**迭代的数组**当成 **只读（readonly）** 的。
*   **开启后**：允许我们在遍历的过程中，直接修改**迭代的数组** 即`x` 的值。
*   **应用**：数值微分需要反复修改 `x` 的值（`+h`, `-h`），所以必须开启此权限。

## nditer 的四种核心用法

### 1. 基础用法：纯粹的值遍历
最朴素的用法，不管数组是几维的，它都会把它“拉平”了挨个吐给你。
```python
for x in np.nditer(a):
    print(x)
```

### 2. 进阶用法：一边遍历一边修改
如果你想把数组里的每个数都修改，但不想创建新数组，就可以用这个模式。
```python
with np.nditer(a, op_flags=['readwrite']) as it:
    for x in it:
        x[...] = x * 2  # 注意：必须用 x[...] 来表示要修改的修改内容
```

### 3. 坐标生成器（当前用法）
既需要改数据，又需要填梯度表。
```python
it = np.nditer(x, flags=['multi_index'], op_flags=['readwrite'])
while not it.finished:
    idx = it.multi_index  # 拿到坐标
    # ... 计算梯度并填表 ...
    it.iternext()
```

### 4. 高级用法：自动广播遍历
这是 `nditer` 最黑科技的地方。把两个形状不同的数组扔进去，它会按照广播规则自动对齐遍历。
```python
# x是(3,1)的列向量，y是(1,3)的行向量
for a_val, b_val in np.nditer([x, y]):
    # 它会自动把两者都当成 (3,3) 的矩阵来遍历！
    pass
```
比如：
```python
x = [[0],
     [10],
     [20]]  # shape (3, 1)

y = [[1, 2, 3]] # shape (1, 3)
```

广播的时候从右往左对其, 先把x广播为(3, 3)的, 将原本一维的列向量广播为
```python
[[0, 0, 0],
 [10, 10, 10],
 [20, 20, 20]]
```
再把y广播为(3, 3)的, 相当于扩充y的行, 变成
```python
[[1, 2, 3],
 [1, 2, 3],
 [1, 2, 3]]
```
返回的时候还是行优先遍历, 开始 nditer 遍历 (自动广播):
逻辑索引: (0, 0) => x值: 0,  y值: 1     
逻辑索引: (0, 1) => x值: 0,  y值: 2     
逻辑索引: (0, 2) => x值: 0,  y值: 3     
逻辑索引: (1, 0) => x值: 10, y值: 1
逻辑索引: (1, 1) => x值: 10, y值: 2
逻辑索引: (1, 2) => x值: 10, y值: 3
逻辑索引: (2, 0) => x值: 20, y值: 1
逻辑索引: (2, 1) => x值: 20, y值: 2
逻辑索引: (2, 2) => x值: 20, y值: 3

### 5. 广播的非破坏性与底层原理
**核心结论：广播并不会改变原 `ndarray` 的形状或数据！**

它只是在遍历过程中动态地“模拟”了广播效果。

#### (1) 只读视图 (Read-Only View)
`nditer` 为我们提供了一个虚拟的、广播后的“逻辑视图”。在这个视图里，你看到了 `(3,3)` 的矩阵，但真正的物理内存里，`x` 依然是 `(3,1)`，`y` 依然是 `(1,3)`。

#### (2) 零步长机制 (Zero Stride Magic)
NumPy 是如何做到不复制数据就能“假装”数据变多了呢？答案是 **Strides (步长)**。

*   **正常情况**：假设是 `int32`，向前移动一个元素，内存地址要加 **4** 个字节。
*   **广播维度**：NumPy 耍了个滑头，把广播维度的步长设为 **0**。
*   **效果**：当迭代器在广播维度上“移动”时，内存地址加 **0**。也就是说，**它在原地踏步，反复读取同一个内存地址的值**。

这就是为什么广播操作既快又省内存——因为它根本没有复制数据。

## 深度理解：关于内存、上下文与广播 (用户总结)

### 1. 内存遍历机制 (Contiguous Memory Buffer)
*   **理解**：当把一个 `ndarray` 作为实参输入迭代器中，迭代相当于按照这个 `ndarray` 的连续内存缓冲区从左到右挨个返回。
*   **术语**：**Contiguous Memory Buffer（连续内存缓冲区）** 或 **Flat Memory（扁平内存）**。
*   **逻辑**：多维数组中的数据在内存中实际上是一条连续的一维数据, 可以说是存在连续内存缓冲区中的。`nditer` 默认按照 **C-Order**（行优先）去遍历这条数据。

### 2. `with` 语句 vs 直接赋值
*   **理解**：`with` 语句用于资源管理（上下文管理器），保证无论是否报错，退出时都会自动关闭迭代器（`it.close()`）。
*   **应用**：在简单脚本中直接赋值（`it = np.nditer(...)`）也可以，但在涉及复杂读写或资源安全时，推荐使用 `with`。

### 3. `multi_index` 的作用
*   **理解**：将 `flags` 设置为 `['multi_index']` 后，迭代器对象就可以通过 `multi_index` 属性来返回当前元素的索引。
*   **机制**：迭代器不再是“盲跑”，而是每走一步都会计算当前的行列坐标，虽然稍微牺牲一点速度，但提供了必要的定位信息。

### 4. 广播迭代 (Broadcasting Traversal)
*   当把两个 `ndarray` 以参数形式放入迭代器类中 `np.nditer([x, y])`，首先会将两个 `ndarray` 广播为相同 shape。
*   然后在迭代的时候会返回两个元素, 一个元素是x的, 一个元素是y的.
*   返回顺序是按照两个ndarray的数据在内存中的连续内存缓冲区从左到右逐个返回的.
