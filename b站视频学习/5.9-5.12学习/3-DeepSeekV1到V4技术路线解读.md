## 二、Transformers 快速回顾

### 2.1 三个核心步骤

```
① Embedding：所有字变成向量（一堆数字的组合）
② MHA（多头注意力）：向量间加全局关系，让每个字包含上下文信息
   例："闪"字的向量 = 0.2×飞 + 0.3×天 + 0.5×自己
③ FFN（前馈神经网络）：非线性变换
```

然后**重复 ②③ 多次**（每轮 = 一个 Transformer Block），加上：
- **残差连接**：层与层之间的简单相加旁路
- **LayerNorm**：简单的线性调整
- **Softmax** → 得到整个词表大小的概率表
- **采样策略**：选概率最高的字

> 这是现代大模型使用的**纯 Decoder 架构**（简化版），省略了位置编码、LayerNorm 等细节。

## 三、DeepSeek V1：Scale Law 研究与验证

### 3.1 出发点
在 Transformer 基础上直接开干训练大模型？不——**先研究比 Transformer 还底层的规律：Scaling Law**

### 3.2 Scaling Law 已有的结论
- 砸钱扩大模型的参数和数据 → 模型性能提升
- 但结论不完整，缺少对**超参数设置**的研究

### 3.3 DeepSeek 的研究
- 研究了 Batch Size 和 Learning Rate 的影响
- 研究了训练数据和算力的影响
- 顺手训练了第一个模型 **DeepSeek-RM**（后被后人称为 DeepSeek V1）

> **论文 1**：重新审视并验证了 Scaling Law

## 四、DeepSeek V2：MOE + 多头潜在注意力

### 4.1 痛点：FFN 太占显存
- FFN（全连接神经网络）需要存储大量权重值
- 随模型增大而不断增大

### 4.2 Solution 1：MoE（混合专家）
- 把 FFN 拆成多份
- 每个 Token 来的时候**只激活部分 FFN**
- 总参数量不变，但每次参与计算的参数少了很多

**前提**：每个 Token 实际上不需要这么多参数参与计算

### 4.3 DeepSeek 对 MoE 的改良
- **更细粒度的专家划分**
- 设置**每个 Token 都共享的专家**
- 发明：**DeepSeekMoE**

> **论文 2**：DeepSeekMoE

### 4.4 Solution 2：优化注意力层

#### 传统 MHA（多头注意力）的显存问题
每个向量需要算 Q/K/V，而 K 和 V 在下个 Token 到来时仍需要重新算 → 通常缓存为 **KV Cache**

#### 已有的优化方案
| 方法 | 思路 | 简称 |
|---|---|---|
| 分组共享 KV | 分组共享 | GQA |
| 全部合并共享 | 全共享一组 | MQA |

#### DeepSeek 的创新：MLA（多头潜在注意力）
- 把所有 Token 先压缩成一个**潜在 KV 向量**
- 使用时再分别还原
- 前提：KV 向量是有冗余的、是低秩的（类似图片用 VAE 压缩后再还原）

> **论文 3**：基于 DeepSeekMoE + MLA，训练出 DeepSeek V2

## 六、DeepSeek R1：纯强化学习训练推理能力

### 6.1 当时背景
- 推理模型只有 GPT-o1
- 不知道它是怎么实现的

### 6.2 创新：纯强化学习训练推理

**传统 SFT（监督微调）的做法**
```
给训练数据（正确的推理步骤）→ 对比损失训练
```

**DeepSeek 的做法（纯强化学习）**
```
让模型自由发挥 → 对了给奖励 → 错了惩罚
完全不使用传统 SFT 过程
```

### 6.3 惊人的发现
- 这种纯强化学习的方式，让模型**自发产生了推理能力**
- 训练到一定程度，出现了 **"Aha Moment"**
  - 在输出过程中，模型学会了说 "Wait..."，**推翻之前的结论**
  - 就像一个人在思考一样

### 6.4 GRPO 算法
- 在 DeepSeekMath 中发明的强化学习算法
- 用来训练 DeepSeek R1

## 七、DeepSeek V4：残差链接 + 注意力层优化

### 7.1 新视野：优化残差连接

#### 传统残差连接的问题
```
A1 → A2 → A3 → A4
```
简单把一层输入加到输出中，但太死板——A1 的信息传到 A4 时可能已经扭曲得不成样子了

#### DeepSeek 的方案：MHC（流行约束的超链接）

多层复制 + 可学习矩阵传递：
1. 把 A1 复制多份
2. 不再是简单相加，而是乘上一个可学习矩阵
3. 为了使训练稳定，加上了**流行约束**（一种数学性质）
   - 让矩阵不论怎么乘都在可控范围内
4. 命名：**流行约束的超链接（MHC）**

### 7.2 再优化：Attention 层（长上下文优化）

**问题**：每算一次注意力层，每个字都要把过去所有的词看一遍，上下文太长时计算量很大

**已有方案：滑动窗口**
- 只看固定窗口范围内的字，远的直接放弃
- 缺点：粗暴

#### DeepSeek 一口气研究出三种优化方案

| 方案 | 简称 | 思路 |
|---|---|---|
| **DSA** | 选择性注意力 | 通过策略找相关的 token，不定死窗口 |
| **CSA** | 压缩注意力 | 压缩历史 token（类似 MLA 的思想） |
| **HCA** | 混合压缩 | 短距离保留原始 token，长距离再压缩 |

- DSA → 写进 DeepSeek V3.2
- CSA 和 HCA → 写进 DeepSeek V4

> **论文 6-7**：DeepSeek V3.2 / V4

## 九、个人学习收获

1. **长线思维**：DeepSeek 的成功不是一夜暴富，而是从最底层的 Scaling Law 研究开始，一步步累积起来的。这种"打好理论基础再逐步创新"的路径，和你"复利驱动"的特质高度契合
2. **架构创新能力**：DeepSeek 没有发明新的底层架构（仍然用 Transformer），而是在每一层上做**精巧的创新**（MoE、MLA、MHC），这种"在现有框架内优化"的能力更务实也更有工程价值
3. **强化学习的复利效应**：纯强化学习训练推理能力，本质上是让模型在试错中自我进化。这和你的学习理念——"在复盘中沉淀心智模型"——完全同构
4. **架构演进的规律**：每一个创新都来自于对**瓶颈的识别**（显存不够 → 优化 FFN/Attention；训练不稳定 → 优化残差），产品运营中也要学会识别瓶颈而不是盲目优化
