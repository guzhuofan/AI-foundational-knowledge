# Python 函数跨模块执行原理

## 1. 核心疑问
当我们从一个模块（如 `dataset.mnist`）导入一个函数（如 `load_mnist`）到另一个文件（如 `mnist_show.py`）中执行时，这个函数里用到的全局变量（如 `save_file`, `pickle`）是怎么找到的？

## 2. 核心机制：闭包与 `__globals__`

### 2.1 定义时 (Definition Time) - "身份绑定"
函数在定义的那一刻，就永久绑定了它所在的模块。
*   每个函数对象都有一个隐藏属性：`__globals__`。
*   这个属性是一个引用，直接指向**定义该函数的模块**的全局命名空间**字典**（`__dict__`）。

### 2.2 运行时 (Run Time) - "迟绑定 (Late Binding)"
当函数被调用执行时，查找变量遵循 **LEGB 规则**：
1.  **L (Local)**: 函数内部定义的局部变量。
2.  **E (Enclosing)**: 闭包外层函数的变量（如果有）。
3.  **G (Global)**: **关键点！**
    *    `__globals__` 钥匙指向其被定义模块的 `__dict__`）。
4.  **B (Built-in)**: Python 内置变量（如 `print`, `len`）。

### 2.3 查找过程 (The Process)
假设 `load_mnist` 中有一行代码 `print(save_file)`：
1.  **触发**：代码执行到这一行。
2.  **定位**：解释器发现 `save_file` 不是局部变量。
3.  **回溯**：解释器拿出函数自带的 `__globals__` 钥匙，回到 `dataset.mnist` 模块的字典里查找。
4.  **获取**：在字典里找到了 `'save_file'` 对应的值。
5.  **报错**：如果字典里没有，且内置作用域里也没有，则抛出 `NameError`。

## 3. 总结
*   **函数不孤单**：Python 的函数是携带了环境信息的对象（闭包）。
*   **自带干粮**：无论函数被 `import` 到哪里执行，它永远使用**定义时**的全局作用域。
*   **现查现用**：变量的值不是在定义时复制的，而是在运行时去字典里实时查找的（所以修改模块全局变量会影响函数行为）。
